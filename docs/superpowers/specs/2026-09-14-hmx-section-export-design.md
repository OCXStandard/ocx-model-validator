# HMX Cross-Section Export — Design

**Date:** 2026-09-14
**Status:** Approved

## Goal

Export the cross-section produced by `validator section create` as a Nauticus Hull
HMX XML document (`HullModel` root) that Nauticus Hull / Poseidon can load, making
XML the default output format while keeping JSON available behind a flag.
`validator section plot` accepts both formats.

## References

- Schemas: `docs/superpowers/HullModel_HMX.xsd`, `docs/superpowers/CrossSection_DLX.xsd`
  (included by HullModel as `CrossSection_2DLX.xsd` — filename mismatch handled by
  renaming the copy used for validation), `docs/superpowers/Base.xsd`.
- Sample document: `docs/ISSCFrame170.hmx`.
- Profile type-code mapping: `docs/superpowers/ProfileMappingWithProperties (1).xlsx`.

## CLI

```
validator section create MODEL.3docx (--frame FR20 | --x 50000)
    [--format xml|json]        # default: xml
    [--rule-set DNV|RV5|CSR-H] # default: DNV; selects the ShipData branch
    [-o OUT]
validator section plot SECTION.{hmx,json} [-o OUT.svg]
```

- Default output name: model stem + location suffix + `.hmx` (xml) or `.json` (json),
  reusing `_default_section_output` with a format-dependent extension.
- `section plot` selects the loader by extension: `.hmx`/`.xml` → HMX import,
  otherwise JSON.

## Top-level HullModel mapping

One exported file contains exactly one `Scantling` (one section per `create` call).

| HMX element | Source |
|---|---|
| `ShipData@VesselId` | OCX vessel name/id |
| `ShipData@ShipType` | `"Other"` (not available in OCX) |
| `ShipData@Info` | `"Generated by ocx-model-validator from <file>"` |
| Rule branch (`DNV`/`RV5`/`CSR-H`) | per `--rule-set`; DNV emits `ApplicableRules RuleSet="DNV-1A1" RuleEdition=<YYYYMM>` |
| `MainDimensions` | Lbp/L/Lll/LllForwardX from model extent Δx, B from Δy, D from Δz, converted to metres; optional attributes (T, Cb, …) omitted |
| `GeneralShipDataType` | required attributes set to `0` placeholders |
| `MaterialData` | `E=206000`; `SigmaFBott`/`SigmaFDeck`/`SigmaFMid` from plate yields by z-band (bottom/deck/between); fallback 235 |
| `FrameTable` | existing `FrameTable`: `FrameRef="AP"`, `FrameOffset` in m, `Spacing` rows (first entry `FrameNo="Stern"`), spacing in metres |
| `Compartments` | one `Compartment` per IR compartment (see below) |
| `CrossSections/Scantling` | see below |

Non-fatal extraction warnings are logged via loguru and embedded as one XML comment
near the document root (the schema has no warnings slot).

## Compartments mapping

One `Compartment` element per IR compartment:

| HMX | Source |
|---|---|
| `@Id` | sequential integer string (`"1"`, `"2"`, …), stable within the document |
| `@Name` | compartment name (fallback id) |
| `@Type` | OCX `compartment_purpose` mapped to the HMX enum: ballast → `BallastWaterTank`, fuel/HFO/MDO → `FuelOilTank`, fresh → `FreshWaterTank`, cargo → `CargoHold`, void → `VoidSpace`; fallback `Undefined` + warning |
| `General@Volume` | volume (m³) |
| `General@CgX/CgY/CgZ` | COG (mm, rounded to int) |
| `General@TopOfAirPipe` | air pipe height (mm) |
| `General@Length` | extent Δx (mm) |
| rule branch | `CSRH` when `--rule-set CSR-H`, else `RV5`; `OverPressure` = relief-valve pressure (kPa ≈ kN/m²), `PressureValveFitted=true` when a relief valve pressure is present |
| `Geometry/BoundingBox` | compartment extent (required by schema); zeros + warning when unresolvable |

**SEGMENT `LeftCompartment`/`RightCompartment`:** for each SHAPE segment, offset
the midpoint ± ε along the in-plane segment normal and test the offset points
against the bounding boxes of compartments whose x-range contains the section x.
Left/right follows the traversal direction (2D cross product in the y-z plane).
The attribute is omitted when no unique compartment matches (optional in schema).

## Bilge arc (SEGMENT Radius)

Goal: model the bilge — always a circular arc — correctly instead of a chord.

- **Radius inference:** scan the plate `outer_contour` (composite curve) for
  `IrCircumArc3D`/`IrCircle3D` segments whose circle-plane normal is ≈ parallel
  to the global x-axis (the transverse edge arcs of the bilge strake). Radius and
  centre come from the existing `_circle_from_three_points`; when several arcs
  qualify, pick the one nearest in x to the section plane.
- `SectionPlate` gains additive fields `radius_mm`, `arc_center_y_mm`,
  `arc_center_z_mm` (unsigned radius + arc centre in section coordinates); the
  JSON document includes them.
- The HMX writer emits the chained SHAPE segment with `Radius=±r`: positive when
  the radius vector rotates counterclockwise while traversing the segment (per
  the XSD), computed from the traversal direction versus the arc centre. The
  segment endpoint remains the arc end point.
- `PLATE Width` for arc plates = arc length (r·θ from the endpoints and centre),
  not the chord length.
- Fallback: no transverse arc found → straight segment (`Radius=0`); a warning is
  emitted when the contour contains arc segments (suspected curved plate).
- The HMX importer/plot uses chord endpoints; SVG arc rendering is out of scope.

## Scantling mapping

### Panel SHAPE — segment chaining

The section builder yields per-panel disconnected plate segments
`(y1,z1)–(y2,z2)`. The writer chains segments whose endpoints coincide within
**1 mm** into ordered polylines:

- `NODE` = first point of the chain; one `SEGMENT` per subsequent vertex.
- `Radius=0` for straight segments; bilge/arc plates carry the inferred signed
  radius (see *Bilge arc* above). `Girder="Undefined"`.
- A panel producing several disconnected chains emits several `PANEL` elements
  with the same `Name` (as the sample does for port/starboard SHELL).
- Required empty elements `CORRUGATED`, `CUTOUTS`, `TRVSTIFFS` are emitted;
  `BENDEFF` = `SHEAREFF` = `100`.

`Level1Position` heuristic per segment: horizontal at min-z → `GBOTTOM`;
vertical at |y|max → `SIDE`; horizontal at max-z → `GDECK`; else `Undefined`.

### PLATE rows

One `PLATE` per chained segment, in chain order:

| Attribute | Value |
|---|---|
| `Width` | segment length (mm) |
| `RefCode` | `CURVE` |
| `Thickness` | plate thickness (mm) |
| `Yield` | material ReH (MPa); `0` + warning if unresolved |
| `MaterialId` | index over distinct yield values in the document |
| `Material` | `STDSTEEL` |
| `Side` | `LEFT`/`RIGHT`/`CENTER` by mean-y sign of the chain (CENTER if \|mean y\| < 1 mm) |

### LSTIFF rows

Each stiffener is assigned to the nearest chain of its panel; stiffeners with no
resolvable chain are skipped with a warning.

| Attribute | Value |
|---|---|
| `Position` | arc length of the stiffener (y,z) projected onto the chain |
| `RefCode` | `CURVE` |
| `Type` | see mapping below |
| `H`,`BF`,`T`,`TF` | numeric profile dimensions (mm); `0` + warning if missing |
| `WebAngle` | angle of `web_dir` from the Y-axis, normalised to [0,360) |
| `FlAngle` | `90` if WebAngle < 180 else `270` (assumption: flange toward centreline) |
| `Span` | `STDSPAN` |
| `Yield` | material ReH (MPa) |
| `MaterialId` | as for plates |
| `K` | `0` |
| `BuckStiff` | `false` |
| `RusCode` | `""` |

Type-code mapping (from the mapping spreadsheet):

| IR section class | HMX Type | Dimensions |
|---|---|---|
| `IrFlatBarSection` | 10 | H=height, T=width; BF=TF=0 |
| `IrBulbFlatSection` | 20 | H=height, T=web thickness; BF=TF=0 |
| `IrLSection` | 31 | H, BF=width, T=web t, TF=flange t |
| `IrLSectionOvershootFlange` | 35 | idem |
| `IrLSectionOvershootWeb` | 36 | idem |
| `IrTSection` | 40 | idem |

Unsupported section types → skip stiffener with warning.

### Scantling header

- `IDDATA/NAME` = frame label (e.g. `FR170`) or `x<pos>`; `DATE` = ISO date;
  `SIGNATURE` = `ocx-model-validator`; `COMMENTS` = source file.
- `POSITION/DISTAP` = section x in metres; `MIDSHIP` = true if within 5 % of Lbp/2.
- `MATERIAL` `YIELDBOTT`/`YIELDDECK`/`YIELDBETW` from plate yields by z-band.
- `MISC`: `STRUCTTYPE=SECTION`, `HSIDE=0`, `STDSPAN` = frame spacing at the
  section x (mm), `STDSPACE` = median stiffener spacing (mm).

## Architecture

- **`sections/hmx_export.py`** (new): `build_hmx(vessel, cross_section, frame_table,
  source_file, rule_set) -> lxml Element` and `save_hmx(...)`. Pure helpers:
  `_chain_segments`, `_arc_position`, `_level1_code`, `_lstiff_type`, `_ship_data`.
  Consumes only `CrossSection`/`FrameTable`/IR — no OCX imports.
- **`sections/hmx_import.py`** (new): `load_hmx_document(path) -> dict` rebuilding
  the existing `nh-cross-section/1` dict (plate endpoints recovered by walking
  PLATE widths along the SHAPE chain; stiffener (y,z) from arc-length positions),
  so `render_svg` and other JSON-document consumers stay untouched.
- **`section_builder.py`**: add numeric `h_mm`, `bf_mm`, `tw_mm`, `tf_mm` fields to
  `SectionStiffener`, and `radius_mm`, `arc_center_y_mm`, `arc_center_z_mm` to
  `SectionPlate` (all additive; the JSON document gains these fields).
- **`cli.py`**: `--format`/`--rule-set` options on `section create`; plot loader
  dispatch by extension.

## Error handling

Same philosophy as the JSON path: degrade gracefully and collect warnings.
Required-by-schema numeric attributes missing from the model are written as `0`
with a warning. `SectionError` is raised only when nothing intersects the plane.
The HMX importer validates the root element and required blocks and raises
`SectionError` on malformed input.

## Testing

- Copy the three XSDs to `tests/data/hmx_schema/`, renaming the cross-section
  schema to `CrossSection_2DLX.xsd` so the include resolves. Add `xmlschema` as a
  dev dependency; a test validates the exported document against the XSD 1.1
  schema set.
- Unit tests: segment chaining (ordering, multiple chains, tolerance),
  arc-length positioning, type-code mapping, ShipData branch per `--rule-set`,
  frame-table serialization, Level1Position heuristic, compartment mapping
  (type enum, bounding box, left/right segment assignment), bilge radius
  inference (arc detection, signed radius, arc-length plate width, straight
  fallback with warning).
- Round-trip: create → export `.hmx` → `load_hmx_document` → `render_svg`
  succeeds; CLI integration test mirroring the existing JSON one.

## Out of scope

- HMX `Loads`, `GirderPositions`, `MomentsAndShearForces` blocks
  (all optional in the schema).
- Curved SHAPE segments other than the inferred bilge/plate arcs, cutouts,
  transverse stiffeners.
- SVG rendering of arc segments (plot uses chord endpoints).
- Importing HMX files not produced by this exporter (the importer targets
  round-trip/plot support, not general HMX ingestion).
